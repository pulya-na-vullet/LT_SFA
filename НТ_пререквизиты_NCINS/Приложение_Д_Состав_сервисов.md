# Приложение Д. Состав сервисов (паспорт инфраструктуры)

**Модуль:** NCINS в SFA (`ufr-eos-ul-ncins`)  
Версия: 0.2  
Дата: 16.09.2026

Это **не** пять постановок на НТ. Ниже — состав объекта тестирования из helm/config,
чтобы не дублировать его в анкете.

Исходники сервисов в этом репозитории **отсутствуют**. Репозитории — проект NCINS
(`ufr-eos-ul-ncins-*`), не NSSFA.

---

## 1. `ufr-eos-ul-ncins-core-api` — ядро

Ядро модуля: REST под шлюзом, Feign на UMP и NIB, Kafka producer, Redis, OBIP / AC / Sign-online / WS.

| | |
|---|---|
| Образ | `eco.binary.alfabank.ru/ufr-eos-ul-ncins-core-api` |
| Реплик | 2 |
| Базовый путь | `/ufr-eos-ul-ncins-gateway-router-api/ufr-eos-ul-ncins-core-api` |
| OpenAPI | `/v3/api-docs` (через gateway, сессия не требуется) |
| Единственный известный бизнес-метод | `POST /v1/ins-contracts` (из `ump-main`; ответ в том документе `200 {"OK"}`) |
| Остальные методы | `_TBD_` |

OAuth2 client_credentials: реалмы `ump` и `corporate`.  
Retry: Feign 3 попытки, resilience4j 3 попытки.  
Кэш Redis 60 мин: accounts / manager / sign / client.  
Логи: payload + pretty-print; игнор health/swagger и `application/pdf`.

На НТ это **основной** backend пользовательских UC и входящего create-contract.

---

## 2. `ufr-eos-ul-ncins-gateway-router-api` — транзит

Общий образ `ufr-eos-gateway-router-api`. Нагрузка = сумма запросов, которые через него идут.
Отдельный UC «нагрузить gateway» не нужен: он участвует во всех HTTP к API.

| Пути | Сессия |
|---|---|
| `/ufr-eos-ul-ncins-core-api/**` | `sessionHeaderFlow` — нужен `client-session` `/session/get-info` |
| `/ufr-eos-ul-ncins-module-info-api/**` | не проверяется |
| `/ufr-eos-ul-ncins-access-checker/**` | не проверяется |
| `/ufr-eos-ul-ncins-core-api/swagger-ui/**`, `/v3/api-docs/**` | не проверяется |
| `/${roles-model-api.host}/**` | не проверяется |

Health `/admin/health`, метрики `/actuator/prometheus` — разные actuator-базы, учесть в scraping.

## 4. `ufr-eos-ul-ncins-access-checker` — диагностика

Образ `ufr-access-checker`, `runAsUser: 0`.  
`SERVICE_WHITE_LIST` — какие приложения этот инстанс обслуживает, **не** RBAC пользователей:

```
ufr-eos-ul-ncins-core-api
ufr-eos-ul-ncins-module-info-api
ufr-eos-ul-ncins-access-checker
ufr-eos-ul-ncins-ui
```

Проверяет 13 групп / 25 точек (Kafka, 2 Keycloak, NIB, UMP, 5 UFR HTTP, Redis×6, Redisson×6).  
`GIT_ENABLED=true`. Swagger выключен.

**В профиль НТ не включать:** это не бизнес-метод. Часто дергать — паразитная нагрузка на все зависимости.

## 5. `ufr-eos-ul-ncins-ui`

Node.js, context `/ufr-eos-ul-ncins-ui`, `NODE_ENV=loading`, tag **1.0.1** (у backend tag в values нет).  
Health `/healthmonitor`. Redis plugin включён.

| `KEYCLOAK_API` | `http://ufrulltmock2:8188` |
| `REDIRECT_HOST` | `ufrulltmock1:8110` |

Утверждение «SPA проксирует API» из кода не следует: типичная схема ЕОС.ЮЛ — статика UI + API через gateway. Подтвердить по UI-репо.

НТ пользовательского пути: либо браузерные скрипты, либо сразу HTTP API (предпочтительнее для профиля). Загрузка JS/CSS не смешивать с ЧПН заявок.
