## Детали

### Keycloak NIB / UMP

| | NIB | UMP |
|---|---|---|
| Token URL | `https://corp-gateway-test.moscow.alfaintra.net/mks-gateway/public/auth/realms/corporate/protocol/openid-connect/token` | `https://idp-api-test.alfaintra.net/auth/realms/ump/protocol/openid-connect/token` |
| Realm | `corporate` | `ump` |
| Grant | `client_credentials` | `client_credentials` |
| Client | `${SFA_NIB_CLIENT_ID}` | `${SFA_UMP_CLIENT_ID}` |
| Scope | `offline_access` | `offline_access` |

На заглушке — выдавать валидный JWT. Секреты из K8s, в git их нет.

Feign retry (оба клиента): period 100 ms, maxPeriod 1000 ms, **maxAttempts 3**.  
resilience4j default: max-attempts 3, wait 1s. При ошибках внешней системы нагрузка может умножиться.

### NIB `corp-ncins-acc-api`

- Feign: `nibNcinsAccClient`
- `client-type: BACKEND`, `channel-id: sfa`, `project-id: ncins`
- `xpin-const: XAAAAA` — **константа заголовка backend-клиента**, не PIN тестового ЮЛ

В UMP finalisation create-contract идёт в этот же хост `POST /v1/ins-contracts` с `A-channelId: ump`.
Параллельно `ump-main` показывает вызов **в SFA** `POST .../ufr-eos-ul-ncins-core-api/v1/ins-contracts`.
Какой путь рабочий для боя NCINS в SFA — `_TBD_` (см. анкету, сценарий UC07).

Payload запроса/ответа со стороны SFA → NIB: `_TBD_` (нужен core-api).

### UMP `ump-application-facade`

- Feign: `umpApplicationFacadeClient`
- Пример создания заявки (из UMP-пререквизитов; канал в том примере `NIB` — для SFA поля канала уточнить):

```http
POST /ump-application-facade/applications?finalVersion=true&fullCreate=true
```

Тело (сокращённо): `externalApplicationIds.systemCode`, `participants` (pin, LEGAL, inn, ogrn),
`products.code=NON_CREDIT_INSURANCE`, `salesChannel.code`, `productProperties`
(programId, даты, paymentType `payment_account`, contractNumber, insuranceSum/Premium, debitAccount).

Параметризация из UMP: `@extAppId` uuid, `@fullName`, `@inn`,
`@contractNumber` по маске `Z6922/888/ABR*****/6`.

Для SFA `systemCode` / `salesChannel` в разных UMP-доках то `NIB`, то `SFA`. Для этого модуля
ожидаем `SFA`, но это должно подтвердить ядро.

### Kafka

| Параметр | Значение |
|---|---|
| Security | SASL_SSL / PLAIN |
| Producer | acks=all, idempotence=true, zstd, retries=10, delivery.timeout.ms=120000 |
| Топик в config | `TO_UMP_PROC_FROM_SYS_TEST` |

Сообщения (из `ump-main`; там `systemCode` указан как **всегда NIB** — для канала SFA перепроверить):

Вернуть управление после подписания (SFA → UMP, `ump.process.from.system`):

```json
{
  "messageName": "SigningDocs",
  "correlationKey": "<applicationId>.NON_CREDIT_INSURANCE",
  "variables": {
    "agreementLink": "<uuid>",
    "id": "<applicationId>"
  }
}
```

Завершение оплаты (SFA → UMP):

```json
{
  "messageName": "paymentFinished",
  "correlationKey": "<applicationId>.NON_CREDIT_INSURANCE"
}
```

UMP → SFA (принять подписание), топик `ump.process.to.system`:

```json
{
  "applicationId": "<uuid>",
  "correlationKey": "<applicationId>.NON_CREDIT_INSURANCE",
  "messageName": "SigningDocs",
  "variables": { "inn": "...", "programId": 1 }
}
```

Ожидаемое время в UMP: отдать/принять подписание — 0,5 сек на мок; **ожидание подписания 20 мин**;
ожидание `paymentFinished` — 1 мин. Это таймеры UMP, не SLA HTTP SFA.

### Redis

Живой кластер ЛТ, 6 узлов, prefix `ncins:core:api`, `failover-cache: false`.  
Кэши: `accountsInfo`, `managerInfo`, `signInfo`, `clientInfo` — TTL **60 мин**.  
ЧПН на accounts/customers/sign **не равна** ЧПН API: часть запросов не дойдёт до внешней системы.

### accounts-api

- Заголовки SFA Core: `external-user-code: NCINS`, `registration-id: sfaul-ncins`
- Фильтр включён: валюта `RUR`, тип `CA`, бухрежим `100`
- Тестовые счета вне фильтра сценарий сломают

### roles-model / client-session

- Доступ к модулю: permission `NCINS_UL_ACCESS`, `requiredSessionLevel: 1`
- У операции `access-ncins` стоит `checkRoles: false` — нельзя утверждать, что `roles-model`
  вызывается на каждый запрос `module-info`
- UI на ЛТ: session и roles уже на `https://ufrulltmock1:8110/...`
- Gateway для `/ufr-eos-ul-ncins-core-api/**` ходит в `.../session/get-info`
